# 01. Вход аналитика в существующий проект

[Главная страница](../README.md)

## Известно из постановки

В приложении один владелец учётной записи пользуется несколькими устройствами. Семейных профилей, тренеров и совместного дневника в этом объёме нет. Регистрация, оплата и подписка обязательны. Главная практическая функция — выбор тренировки, запись факта, расчёт расхода энергии и прогноз. Отличительная особенность продукта — 3D-визуализация предполагаемого телосложения. Фото всегда остаются на устройстве; другие тренировочные сведения можно передавать в дальнейшем только по разрешению пользователя. Кейс гипотетический; завершать исходное приложение не требуется.

Одна учётная запись принадлежит одному человеку. Тестовая вторая учётная запись нужна для проверки изоляции, а не добавляет семейный режим.

## Исходная точка, проверенная по репозиторию

Зафиксирован [коммит 214a1a5](https://github.com/branch-danya-dev/trening/tree/214a1a5eea48f1cf115fdbff898b9d8d39547187). Сведения ниже относятся к нему, не к будущим изменениям ветки.

| Компонент | Факт из исходников | Следствие для аналитика |
|---|---|---|
| WorkoutCalculator.Core | Модели тренировки и расчётное ядро C# | Не переписывать формулы под новый API без отдельной задачи |
| Desktop и Cli | Существующие интерфейсы приложения | Не объявлять все клиенты уже использующими общую серверную часть |

| PhotoStore.cs | Фотосессии в IndexedDB, перенос архивом | Сохранить локальность фотографий; не путать архив с облачной синхронизацией |

## Роль в гипотетической команде

Аналитик уточняет потребности, формализует данные и взаимодействие, согласует правила с владельцем продукта и разработчиками, готовит условия приёмки. Он не присваивает себе написание существующего кода, решение научной задачи прогнозирования тела или коммерческий запуск платежей.

Сначала фиксируется текущая версия, затем выбирается пользовательский сценарий, выявляются противоречия и только после этого проектируются изменения. Условная команда: владелец продукта, Scrum Master, специалисты разработки, системного анализа, проверки и визуализации. Это состав для моделирования процесса, не факт найма этих людей.

## Предложенные границы первой версии

Включить ходьбу и бег на дорожке/улице; локальные записи и расчётные снимки; базовую 3D-визуализацию; индивидуальный вход; ручную покупку ограниченного периода подписки; проверку доступа на другом устройстве.

Не включать облачный дневник, загрузку фотографий, автоматические списания, врачебные назначения, обучение нейросети, подключение часов и магазин мобильных приложений. Вопросы о них сохраняются в [решениях](08-решения.md), а не исчезают из развития продукта.
