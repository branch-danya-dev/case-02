## Предлагаемое устройство

На устройстве: интерфейс, локальный дневник, расчётное ядро, параметры и 3D-визуализация. На сервере: регистрация, сеансы, тарифы, платежи и периоды доступа. Внешний платёжный сервис отвечает за ввод реквизитов и состояние денежной операции.

Для продукта рассматривается один сервер на ASP.NET Core и PostgreSQL. Разделение на модули не означает отдельные микросервисы. Брокер сообщений и Kubernetes не добавлены: подтверждённого требования к ним нет. В стенде API и имитатор запускаются раздельно, поскольку именно границу внешней интеграции нужно проверить.

## Данные

| Сведения | Где находятся | Что важно |
|---|---|---|
| Адрес входа и идентификатор владельца | Сервер | Фраза «все личные данные локальны» не относится к необходимым сведениям учётной записи |
| Коды и ключи сеансов | Код передаётся по каналу входа; на сервере только проверочное значение | В стенде почта заменена отдельным демонстрационным методом |
| Платёжные реквизиты | Только платёжный сервис | Наш API не принимает номер карты и проверочный код CVV |
| Тариф, сумма, состояние и период доступа | Сервер | Нет массы тела или содержания тренировок |
| Записи тренировки и исходный профиль расчёта | Устройство | Смена пользователя в интерфейсе не присваивает эти записи другой учётной записи автоматически |
| Фото, уменьшенные копии, силуэты и признаки, полученные из фото | Устройство | Не допускается обход запрета через отправку копии или изображения в другом формате |
| Результаты и 3D-прогноз | Устройство | Отображается происхождение и версия, а не обещание точного будущего |

## Несколько устройств без передачи дневника

Вход на втором устройстве загружает сведения о подписке. Он не копирует тренировки. Это ограничение явно отображается пользователю. Синхронизация замеров и дневника — будущая функция с отдельным включением и выбором категорий. Фотографии исключены даже при её включении.

Будущая функция должна определить отзыв разрешения, удаление ранее переданных данных, сроки хранения, конфликты версий и восстановление после обрыва. Наличие переключателя само по себе не решает эти вопросы. В первой версии отсутствуют соответствующие HTTP-методы и серверные таблицы.

## Работа без интернета

Базовый дневник и уже сохранённые результаты доступны локально. Для платных возможностей предлагается подписанное сервером разрешение с ограниченным сроком, например не более 24 часов и не дольше оплаченного периода. Число 24 часа — предложение для обсуждения, не заданное соглашение об уровне обслуживания (SLA).

Стенд возвращает только информационные права `proofKind=unsigned-demo`: **это не разрешение для защищённой автономной работы**. Подпись и проверка автономного разрешения не реализованы. Необходимо учитывать неверные часы устройства и ограниченную возможность мгновенного отзыва без сети. Абсолютную защиту локально выполняемой функции от владельца устройства не обещаем.

## Безопасность до выпуска

Для продукта требуются защищённый транспорт, промышленный способ доставки входа, защита от перебора и злоупотреблений, управление секретами, контроль происхождения запросов и журналирование без содержимого дневника. Ключи сеансов браузерного клиента не сохраняются в localStorage — хранилище браузера — как часть дневника; выбранную схему входа и обновления сеансов необходимо проверить отдельно.

Запрос с идентификатором чужого платежа (`paymentId`) не раскрывает владельца. Идентификатор сам по себе не является разрешением. Сигнал платёжного сервиса не является доказательством оплаты: сервер сверяет состояние через доверенный запрос и проверяет сумму, валюту и связь с собственной операцией.

Нейросеть будущей версии не получает фото на сервер. Допустимы локальная обработка или, при отдельном разрешении, обработка разрешённых численных данных. Правдоподобие изображения оценивается отдельно от качества прогноза.
