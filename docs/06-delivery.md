# 06. Scrum с практиками Kanban

[Главная страница](../README.md) · [Доска Markdown](../planning/board.md) · [Интерактивная локальная доска](../planning/board.html) · [Исходный список задач](../planning/backlog.json)

Это **предложенный процесс гипотетической команды**, не история проведённых спринтов. Завершённый аналитический материал и завершённая функция приложения — разные результаты. Доска не показывает продукт готовым только потому, что есть стенд.

## Scrum

Цель продукта: помочь человеку фиксировать тренировки и понимать предполагаемые изменения тела через расчёты и 3D-визуализацию без обязательной передачи личного дневника.

Владелец продукта определяет ценность и порядок общего списка задач. Scrum Master помогает команде применять Scrum и устранять препятствия. Аналитик входит в межфункциональную команду создания результата вместе с разработчиками и специалистами проверки; не выступает отдельным начальником, выдающим разработчикам весь план.

Предлагаемый спринт — две недели. Планирование: выбрать цель, объём по возможностям команды и план достижения. Ежедневное обсуждение: проверить продвижение к цели и изменить план, не отчёт руководителю. Обзор: проверить работающий результат с заинтересованными участниками. Ретроспектива: выбрать улучшение способа работы. Уточнение будущих задач идёт по мере необходимости, это не отдельный спринт «написать все ТЗ».

Основа: [Scrum Guide](https://scrumguides.org/scrum-guide.html). Двухнедельная длительность и состав команды — допущения кейса, не обязательные правила стандарта.

## Предлагаемые цели последовательных спринтов

| Спринт | Пользовательская цель | Демонстрация в конце, если выполнены критерии |
|---|---|---|
| 1 | Сохранить реальную ходьбу и понять её расчётный результат | Ввод → локальная запись → расчёт с версией → базовая связь с существующей 3D-моделью |
| 2 | Получить оплаченный доступ на своих устройствах | Вход → подтверждённая тестовая оплата → право на другом устройстве без передачи дневника |
| 3 | Не потерять данные и корректно пережить ошибки доступа | Сбой сохранения, истечение/возврат, пропуск уведомления, восстановление и выгрузка |

Это порядок обсуждения, не обещанный календарь. Производительность команды, выполненные story points и метрики скорости не выдумываются. Объём каждого спринта выбирается после уточнения, не назначается автоматически всей таблицей.

## Правила Kanban-доски

Столбцы: «Требует уточнения» → «Готово к обсуждению» → «В работе» → «Проверка» → «Завершено». Препятствие — отметка на карточке с причиной, а не отдельный столбец, скрывающий начатую работу.

Предлагаемые ограничения WIP (work in progress — начатая незавершённая работа): 2 карточки в работе, 2 на проверке. Заблокированные карточки входят в это число. При превышении сначала заканчиваем или помогаем проверить начатое, а не начинаем новые задачи. Принудительного назначения людей доска не делает. Ограничения уточняются с реальной командой.

Исходная доска показывает планируемую разработку: пустые столбцы «В работе/Проверка/Завершено» допустимы и честнее выдуманной истории. HTML позволяет отработать переходы и экспортировать своё состояние. Это локальный тренажёр, не GitHub Projects и не общая доска команды. В GitHub исходное состояние хранится в backlog.json; HTML и Markdown создаются из него. Локальные изменения браузера не меняют репозиторий.

## Критерии завершённости

Definition of Done — общие критерии завершения функции: выполнены её условия приёмки, код интегрирован с приложением, пройдены проверки данных и доступа, документация совпадает с реализацией, ошибки не скрываются, нет утечки личных данных, результат можно показать пользователю. Успешные проверки имитатора не выполняют этот набор за реальный продукт.

«Готово к обсуждению» означает наличие понятного сценария, зависимостей и условий проверки; это локальное соглашение, не дополнительный обязательный элемент Scrum.

## Как анализировать движение работы

После появления реальных дат можно измерять время от начала до завершения, возраст незавершённых карточек, количество завершений и объём незавершённой работы. Пока данных нет, числовые показатели не публикуются. Канбан дополняет Scrum управлением потоком, не заменяет его одной доской: [руководство Scrum.org](https://www.scrum.org/resources/online-kanban-guide-scrum-teams).
